## 1. Основы AJAX и XMLHttpRequest

В данной лабораторной работе статические (захардкоженные) данные были удалены из HTML-кода. Теперь приложение использует **AJAX** (Asynchronous JavaScript and XML) для получения актуальной информации о валютных кассетах с бэкенда.

Для выполнения HTTP-запросов без перезагрузки страницы используется встроенный в браузер объект `XMLHttpRequest` (XHR). Он позволяет отправлять запросы и асинхронно обрабатывать ответы сервера, динамически обновляя интерфейс.

## 2. Модульная архитектура клиентского API

Согласно требованиям, для удобства масштабирования и поддержки кода логика работы с API была вынесена в отдельный слой `modules`.

### 2.1. Класс эндпоинтов (`currencyUrls.js`)
Создан класс, инкапсулирующий все URL-адреса для обращения к серверу. Это позволяет легко менять базовый URL без необходимости переписывать весь код:
```javascript
class CurrencyUrls {
    constructor() {
        this.baseUrl = 'http://localhost:3000/api';
    }
    getCurrencies() { return `${this.baseUrl}/currencies`; }
    // ... методы для других CRUD операций
}
2.2. Класс-обертка Ajax (ajax.js)
Разработан универсальный класс Ajax, который предоставляет удобные методы (GET, POST, PATCH, DELETE) и скрывает в себе низкоуровневую работу с XMLHttpRequest:

JavaScript
class Ajax {
    get(url, callback) {
        const xhr = new XMLHttpRequest();
        xhr.open('GET', url);
        xhr.send();
        xhr.onreadystatechange = () => {
            if (xhr.readyState === 4) this._handleResponse(xhr, callback);
        };
    }
    // ... реализация остальных HTTP-методов
}
3. Проблема кросс-доменных запросов (CORS)
Поскольку фронтенд приложения запускается на порту 5500 (через Live Server), а бэкенд из 4-й лабораторной работы работает на порту 3000, браузер по умолчанию блокирует XHR-запросы из-за политики CORS (Cross-Origin Resource Sharing).

Демонстрация проблемы:
При попытке получить список кассет в консоли браузера (и в интерфейсе) возникает ошибка:
Access to XMLHttpRequest at 'http://localhost:3000...' has been blocked by CORS policy...

Решение для разработки:
В рамках данной лабораторной работы для обхода этого ограничения используется браузерное расширение CORS Unblock. Оно перехватывает запросы и динамически подменяет заголовки, убеждая браузер, что ответ пришел из доверенного источника.

4. Интеграция с интерфейсом и дополнительное задание
В качестве дополнительного задания был реализован отказоустойчивый Single Page Application (SPA) интерфейс банкомата, который элегантно обрабатывает сетевые ошибки и состояния, предотвращая поломку приложения:

Защита от ошибок (Graceful Degradation): Если CORS не разблокирован или сервер недоступен, страница не ломается. Вместо этого выводится стилизованное информационное табло с указанием статуса HTTP и инструкцией по включению расширения.

Динамический рендеринг: При успешном ответе (статус 200) JavaScript-код автоматически генерирует HTML-карточки кассет и выстраивает их в сетку.

Синхронизация с базой: Добавление новых кассет (например, через Postman) моментально отображается в интерфейсе при обновлении страницы благодаря XHR запросам.

5. Инструкция по запуску и проверке
Подготовка бэкенда: Открыть терминал с сервером из 4-й лабораторной работы и выполнить npm run dev (убедиться, что на сервере отключен заголовок разрешающий CORS).

Запуск фронтенда: Запустить файл index.html из текущей директории с помощью расширения Live Server (откроется на 127.0.0.1:5500).

Проверка блокировки CORS: Убедиться, что расширение браузера CORS Unblock выключено. Загрузить страницу — на экране и во вкладке Console (F12) должна появиться красная ошибка CORS.

Успешный запрос: Включить расширение CORS Unblock, обновить страницу. Информационный блок должен стать зеленым, а данные успешно отрисоваться. Работу скрипта можно проверить во вкладке Network (фильтр XHR) панели разработчика.
