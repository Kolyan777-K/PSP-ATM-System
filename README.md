## 1. Основы REST API и CRUD операций

В 4-й лабораторной работе приложение переведено на архитектуру **Client-Server**. Фронтенд больше не хранит данные в себе, а запрашивает их у сервера. Взаимодействие строится на принципах REST (Representational State Transfer) с использованием четырех основных методов:

* **GET** — Получение данных (Чтение списка кассет).
* **POST** — Создание нового ресурса (Добавление новой валюты).
* **PATCH** — Частичное обновление (Изменение резерва при выдаче денег).
* **DELETE** — Удаление ресурса (Демонтаж кассеты).

Это соответствует концепции **CRUD** (Create, Read, Update, Delete), которая является фундаментом любого современного веб-сервиса.

## 2. Архитектура сервера на Node.js и Express

Серверная часть написана на Node.js. Для упрощения работы с маршрутизацией (роутингом) и HTTP-запросами использован фреймворк **Express**.

### Инициализация сервера:
```javascript
const express = require('express');
const cors = require('cors');
const app = express();

// Middlewares
app.use(cors()); // Разрешение кросс-доменных запросов (CORS)
app.use(express.json()); // Парсинг JSON в теле запроса

app.listen(3000, () => {
    console.log('🚀 Сервер V ATM запущен на порту 3000');
});
```

### Пример реализации метода GET (Чтение):
```javascript

});
```

## 4. Тестирование и отладка в Postman

Для проверки работоспособности API без использования фронтенда применялся инструмент **Postman**. С его помощью были протестированы все эндпоинты:

1. **Запрос списка:** `GET http://localhost:3000/api/currencies`
2. **Имитация выдачи:** `PATCH` запрос с JSON телом `{"amount": 500}` на ID конкретной кассеты.
3. **Проверка статус-кодов:**
   * `200 OK` — успешная операция.
   * `404 Not Found` — обращение к несуществующей валюте.
   * `400 Bad Request` — попытка снять сумму, превышающую резерв.

## 5. Реализованные методы API (V ATM)

В рамках расширения функционала системы банкомата были реализованы следующие возможности:

* **5.1. Динамическая выдача:** При совершении операции на фронтенде отправляется `PATCH` запрос. Сервер проверяет наличие средств в `currencies.json` и возвращает обновленное состояние кассеты.
* **5.2. Управление кассетами (POST/DELETE):** Реализована возможность добавления новых валют в систему и удаления существующих через административные запросы.
* **5.3. Обработка CORS:** Настроена политика безопасности, позволяющая фронтенду, запущенному на `localhost:5500` (Live Server), безопасно обмениваться данными с бэкендом на `localhost:3000`.

### Инструкция по запуску:
1. Перейти в директорию `backend`.
2. Установить зависимости: `npm install`.
3. Запустить сервер: `npm run dev`.
4. Убедиться, что в терминале появилось сообщение о запуске на порту 3000.
