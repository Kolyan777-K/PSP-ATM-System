## 1. Алгоритм: Анализ стабильности сети (Строки и циклы)

В рамках выполнения требований к логике приложения был реализован модуль аналитики, который имитирует проверку логов соединения банкомата с сервером. Входящие данные представляют собой бинарную строку, где `1` означает успешный пинг, а `0` — потерю пакета или сбой связи.

**Особенность реализации:** Согласно техническому заданию, алгоритм должен использовать цикл с условием, но **без классического инкрементного счетчика** (такого как `let i = 0; i++`).

Для решения этой задачи применен подход потоковой обработки строки:
1. Цикл `while` выполняется до тех пор, пока длина строки строго больше нуля.
2. На каждой итерации алгоритм считывает первый символ строки.
3. Затем строка "укорачивается" (перезаписывается) с помощью метода `substring(1)`, который отсекает уже проверенный символ.
4. Внутренняя логика подсчитывает максимальную непрерывную последовательность единиц, обновляя рекордный показатель (аптайм).

**Реализация в коде:**
```javascript
checkNetworkStability() {
    let pingHistoryStr = "1101111100110111";
    let maxConnectionUptime = 0;
    let currentUptime = 0;

    while (pingHistoryStr.length > 0) {
        let currentPing = pingHistoryStr.substring(0, 1); // Берем первый символ
        pingHistoryStr = pingHistoryStr.substring(1);     // Отрезаем его от исходной строки

        if (currentPing === '1') {
            currentUptime++;
            if (currentUptime > maxConnectionUptime) {
                maxConnectionUptime = currentUptime;
            }
        } else {
            currentUptime = 0; // Сбрасываем текущий счетчик при обрыве связи
        }
    }
    return maxConnectionUptime;
}
```

## 2. Алгоритм: Расчет среднего номинала кассеты (Коллекции)

Вторая алгоритмическая задача связана с обработкой коллекций данных (массивов). В контексте приложения каждая валюта имеет свой собственный набор допустимых номиналов купюр (например, `[5000, 2000, 1000, 500, 200, 100]` для рублей).

Данные массивы хранятся внутри объекта `denominations`. Алгоритм должен вычислить среднее арифметическое значение загруженных в кассету банкнот для вывода этой информации в блок аналитики интерфейса банкомата.

**Пошаговая логика:**
1. Получение нужного массива из объекта по ключу текущей валюты (`this.data.currency`).
2. Проверка на наличие данных (защита от деления на ноль).
3. Итерация по массиву с помощью метода `.forEach()` для суммирования всех элементов.
4. Деление полученной суммы на длину массива (`length`) и форматирование результата до одного знака после запятой с помощью `.toFixed(1)`.

**Реализация в коде:**
```javascript
calculateAverageDenomination() {
    const currentNotesArray = this.denominations[this.data.currency];
    if (!currentNotesArray || currentNotesArray.length === 0) return 0;

    let sum = 0;
    currentNotesArray.forEach(note => sum += note);

    return (sum / currentNotesArray.length).toFixed(1);
}
```

## 3. Интеграция 3D-графики (Three.js и GLTFLoader)

Для повышения интерактивности приложения и реализации дополнительного задания на страницу детальной информации о валюте внедрен WebGL-рендер трехмерной модели (банковского сейфа или банкомата).

### 3.1. Подключение библиотеки
Библиотека `Three.js` и её дополнительные модули подключаются без использования сборщиков (Webpack/Vite) посредством современной технологии `importmap` прямо в HTML-файле:
```html
<script type="importmap">
  {
    "imports": {
      "three": "[https://unpkg.com/three@0.160.0/build/three.module.js](https://unpkg.com/three@0.160.0/build/three.module.js)",
      "three/examples/jsm/": "[https://unpkg.com/three@0.160.0/examples/jsm/](https://unpkg.com/three@0.160.0/examples/jsm/)"
    }
  }
</script>
```

### 3.2. Создание сцены и рендеринг
Для отображения модели формируется полноценная 3D-сцена, состоящая из:
* **THREE.Scene()** — контейнер для всех объектов и источников света.
* **THREE.PerspectiveCamera()** — камера, имитирующая человеческое зрение с заданным углом обзора и соотношением сторон.
* **THREE.WebGLRenderer()** — движок рендеринга с включенным сглаживанием (`antialias: true`).
* **THREE.DirectionalLight()** — направленный источник света, создающий блики на гранях модели.

### 3.3. Загрузка и авто-центрирование модели
Асинхронная загрузка файлов формата `.glb` осуществляется с помощью `GLTFLoader`. Важной особенностью реализации является алгоритм центрирования: поскольку внешние модели могут иметь смещенный центр координат (pivot point), скрипт автоматически вычисляет математический центр объекта (Bounding Box) и выравнивает его по центру сцены.

```javascript
const loader = new GLTFLoader();
loader.load('/models/atm.glb', (gltf) => {
    const model = gltf.scene;

    // Алгоритм вычисления центра Bounding Box
    const box = new THREE.Box3().setFromObject(model);
    const center = box.getCenter(new THREE.Vector3());
    model.position.sub(center); // Смещение модели

    scene.add(model);
});
```
Для управления камерой мышью (вращение, зум) к сцене привязан контроллер `OrbitControls` с активированным параметром автоматического медленного вращения (`autoRotate = true`).


## 5. Запуск приложения с помощью Live Server

Интеграция ES6-модулей, `importmap` и асинхронная загрузка бинарных 3D-моделей файлов (`.glb`) с жесткого диска вызывают конфликт с политикой безопасности браузеров **CORS** (Cross-Origin Resource Sharing). Запуск проекта простым двойным кликом по `index.html` (через протокол `file://`) приведет к ошибкам в консоли и невозможности рендера 3D-сцены.

**Правильный алгоритм запуска:**
1. Открыть корневую папку проекта в редакторе **Visual Studio Code**.
2. Убедиться, что установлено расширение **Live Server** (от Ritwick Dey).
3. В панели проводника файлов нажать правой кнопкой мыши по файлу `index.html`.
4. Выбрать в контекстном меню пункт **"Open with Live Server"**.
5. Приложение запустится в браузере по умолчанию на локальном хосте (обычно `http://127.0.0.1:5500`).
6. Перейдите на страницу любой валюты, чтобы увидеть работу алгоритмов в блоке аналитики и вращающуюся 3D-модель.
